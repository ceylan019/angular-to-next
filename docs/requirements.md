# Requirements

Every business rule the shop must keep through the migration. Test titles in every suite carry the IDs they cover in square brackets, for example `[BR-C5]`, and `pnpm traceability` turns them into [traceability.md](traceability.md). Known differences, where the legacy app breaks one of these rules on purpose, are listed in [known-differences.md](known-differences.md).

IDs go on test titles, never in comments or variables: an ID on an `it` or `test` title covers that test, and an ID on a group title (`describe` or `test.describe`) covers every test in the group. A test without a body, such as a pending or todo test, covers nothing.

## Layers

- `legacy`: Karma and Jasmine unit and integration tests of the Angular app, in `legacy/src`.
- `web`: Vitest and React Testing Library tests of the Next.js app, in `web/src`. They become required for a rule once its flow is enabled for the next project of the shared suite.
- `api`: Vitest unit and API tests of the shared backend, in `backend/src` and `backend/test`.
- `e2e`: the shared Playwright suite in `e2e/tests`, run against both apps.

A rule needs at least one test in every layer it lists, and CI fails when one is missing. The flow decides when the web tests of a rule become required.

## Allowed gaps

A layer missing from a row is a deliberate gap, not an oversight.

- BR-B8, BR-B9, BR-C1, BR-C3, BR-C4, BR-C6, BR-C7 and BR-K6 list no `api` layer. They are rules of the front ends: labels and disabled buttons, server rendered HTML, the cart (which lives in the browser and never reaches the backend until an order is placed) and the state of the submit button. The backend facts they rely on are covered under other rules: the list returns every candle with its stock under BR-B1, and an order for a sold out candle is rejected under BR-K4.
- The `api` layer of BR-C2 and BR-K1 covers the backend side only: an order line must have a quantity from 1 to 10, and an order must have at least one line. Clamping, the cap message and the redirect from `/checkout` are front end behavior, covered by the other layers.
